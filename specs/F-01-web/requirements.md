# F-01-web — Login y rutas por rol (solo personal)

Brief global: ../asclepio-api/docs/product/features/F-01.md (F-01.AC6; comportamiento observable de AC1, AC3 y AC7)
Contrato: consume 0.2.0 (`POST /api/v1/auth/login`, `GET /api/v1/me`, errores `application/problem+json`, incluidos 401, 403 y 429)
RNF aplicables: RNF-05, RNF-10, RNF-12, RNF-13, RNF-14
Decisiones humanas de partida: PA-F01-1 (JWT de 8 h sin refresh), PA-F01-2 (bloqueo tras 5 intentos, que la API responde con el 401 genérico), PA-F01-3 (un rol por usuario), ADR 0008 (el paciente usa la app móvil, no la web).

Glosario de la spec:
- **Sesión guardada**: el par `{ accessToken, expiresAt }` recibido de `POST /api/v1/auth/login`, guardado según `design.md` D1.
- **Sesión activa**: hay sesión guardada, su `expiresAt` es posterior a la hora del navegador y `GET /api/v1/me` respondió 200 con `kind = "STAFF"`.
- **Ruta protegida**: toda ruta de la web salvo `/login` y `/estado`.
- **Matriz de roles**: la tabla de rutas, roles permitidos y pantalla de inicio por rol de `design.md` D7.
- **Cerrar la sesión (efectos)**: borrar la sesión guardada, vaciar la caché de TanStack Query y cancelar el temporizador de expiración.
- **Mensajes** (textos exactos, PA-1 aceptada): credenciales inválidas "Correo o contraseña incorrectos."; demasiados intentos "Demasiados intentos. Espera {n} segundos e inténtalo de nuevo." (sin `Retry-After` válido: "Demasiados intentos. Espera un momento e inténtalo de nuevo."); conexión "No se pudo conectar con el servidor. Revisa tu conexión e inténtalo de nuevo."; error genérico "No se pudo iniciar sesión. Inténtalo de nuevo."; validación "Escribe tu correo." / "Escribe un correo válido." / "Escribe tu contraseña."; sesión expirada "Tu sesión expiró. Vuelve a iniciar sesión."; solo personal "Esta web es solo para el personal. Los pacientes usan la app móvil."; error de perfil "No se pudo cargar tu perfil."; sin permiso "No tienes permiso para ver esta página.". Las pruebas buscan estos textos literales.

## Requisitos

### Formulario de inicio de sesión
- **R1** (Ubicuo) El sistema deberá mostrar en `/login` un formulario con un campo de correo (`type="email"`, `autocomplete="username"`) y un campo de contraseña (`type="password"`, `autocomplete="current-password"`), cada uno con una etiqueta visible asociada a su control, y un botón de envío "Ingresar". (→ F-01.AC6)
- **R2** (No deseado) Si se envía el formulario con el correo vacío o sin formato de correo, con la contraseña vacía o con una contraseña de más de 128 caracteres, entonces el sistema deberá no llamar a la API, mostrar el mensaje de error junto a cada campo inválido, marcar ese campo con `aria-invalid="true"` y `aria-describedby` apuntando a su mensaje, y mover el foco al primer campo inválido. (→ F-01.AC6)
- **R3** (Por evento) Cuando se envíe el formulario con datos válidos, el sistema deberá enviar `POST /api/v1/auth/login` con un cuerpo JSON `{ email, password }` y sin cabecera `Authorization`. (→ F-01.AC1, F-01.AC6)
- **R4** (Por estado) Mientras la petición de login o la primera `GET /api/v1/me` posterior estén en curso, el sistema deberá mantener deshabilitado el botón "Ingresar", mostrar un indicador de carga con `role="status"` e ignorar nuevos envíos del formulario. (→ F-01.AC6)
- **R5** (Por evento) Cuando `POST /api/v1/auth/login` responda 200, el sistema deberá guardar `accessToken` y `expiresAt` como sesión guardada, pedir `GET /api/v1/me` y, si responde 200 con `kind = "STAFF"`, navegar a la ruta protegida que originó la redirección de R18 (recordada en el estado de navegación, nunca en la query string) si la matriz de roles la permite a su `role`, o en otro caso a la pantalla de inicio de su rol, reemplazando `/login` en el historial. (→ F-01.AC6)
- **R6** (No deseado) Si `POST /api/v1/auth/login` responde 401, entonces el sistema deberá mostrar en un contenedor con `role="alert"` el mensaje de credenciales inválidas, idéntico para cualquier cuerpo `problem+json` recibido (sin mostrar `detail` ni indicar qué campo falló), vaciar el campo de contraseña conservando el correo, no guardar sesión y mover el foco a ese mensaje. (→ F-01.AC1, F-01.AC6)
- **R7** (No deseado) Si `POST /api/v1/auth/login` responde 429, entonces el sistema deberá mostrar en un contenedor con `role="alert"` el mensaje de demasiados intentos, que incluye los segundos de espera tomados de la cabecera `Retry-After` cuando esta exista y sea un entero, no reintentar la petición automáticamente, mantener deshabilitado el botón "Ingresar" durante esos segundos (60 s si la cabecera falta o no es un entero), no guardar sesión y mover el foco a ese mensaje. (→ F-01.AC1, F-01.AC6)
- **R8** (No deseado) Si la petición de login termina sin respuesta HTTP (error de red, CORS o API caída), entonces el sistema deberá mostrar en un contenedor con `role="alert"` el mensaje de error de conexión, conservar el correo, no guardar sesión y mover el foco a ese mensaje. (→ F-01.AC6)
- **R9** (No deseado) Si `POST /api/v1/auth/login` responde con un estado distinto de 200, 401 y 429, entonces el sistema deberá mostrar en un contenedor con `role="alert"` el mensaje de error genérico, mostrar junto al campo `email` o `password` cada `message` de `errors[]` cuyo `field` sea uno de esos dos, no guardar sesión y mover el foco al mensaje con `role="alert"`. (→ F-01.AC6)

### Token, expiración y perfil
- **R10** (Ubicuo) El sistema deberá guardar de la sesión únicamente `accessToken` y `expiresAt`, en `sessionStorage` y bajo una sola clave, sin escribir nada en `localStorage` y sin guardar el correo, la contraseña, `fullName` ni la respuesta de `GET /api/v1/me` en ningún almacenamiento del navegador. (→ F-01.AC6)
- **R11** (Por evento) Cuando la web se cargue con una sesión guardada cuyo `expiresAt` sea posterior a la hora del navegador, el sistema deberá pedir `GET /api/v1/me` y mostrar un indicador de carga con `role="status"` sin renderizar ninguna vista protegida hasta recibir la respuesta. (→ F-01.AC6)
- **R12** (No deseado) Si al cargar la web la sesión guardada tiene un `expiresAt` igual o anterior a la hora del navegador, o no se puede interpretar (JSON inválido, campos ausentes o fecha no válida), entonces el sistema deberá borrarla sin llamar a la API y tratar al usuario como sin sesión. (→ F-01.AC3, F-01.AC6)
- **R13** (Por estado) Mientras exista una sesión guardada, el sistema deberá añadir la cabecera `Authorization: Bearer <accessToken>` a toda petición a la API salvo a `POST /api/v1/auth/login`. (→ F-01.AC3, F-01.AC6)
- **R14** (Por evento) Cuando la hora del navegador alcance el `expiresAt` de la sesión activa, el sistema deberá cerrar la sesión (efectos) y mostrar `/login` con el mensaje de sesión expirada. (→ F-01.AC6)
- **R15** (No deseado) Si una petición enviada con cabecera `Authorization` recibe 401 (incluida `GET /api/v1/me`), entonces el sistema deberá cerrar la sesión (efectos) y mostrar `/login` con el mensaje de sesión expirada. (→ F-01.AC3, F-01.AC6)
- **R16** (No deseado) Si `GET /api/v1/me` termina sin respuesta HTTP o con un estado distinto de 200 y 401, entonces el sistema deberá mostrar un estado de error con `role="alert"` y dos botones, "Reintentar" (repite `GET /api/v1/me`) y "Cerrar sesión", sin renderizar ninguna vista protegida. (→ F-01.AC6)
- **R17** (No deseado) Si `GET /api/v1/me` responde 200 con `kind = "PATIENT"`, entonces el sistema deberá cerrar la sesión (efectos), no renderizar ninguna vista protegida y mostrar `/login` con el mensaje de solo personal. (→ F-01.AC6, F-01.AC7)

### Rutas por rol
- **R18** (No deseado) Si se navega a una ruta protegida sin sesión guardada, entonces el sistema deberá redirigir a `/login` reemplazando la entrada del historial y sin renderizar el contenido de la ruta. (→ F-01.AC3, F-01.AC6)
- **R19** (No deseado) Si con una sesión activa se navega a una ruta protegida cuyos roles permitidos en la matriz de roles no incluyen el `role` de `GET /api/v1/me`, entonces el sistema deberá mostrar la vista "Sin permiso" (un encabezado `h1` y un enlace a la pantalla de inicio de su rol) sin renderizar el contenido de la ruta. (→ F-01.AC3, F-01.AC6)
- **R20** (Por evento) Cuando un usuario con sesión activa navegue a `/` o a `/login`, el sistema deberá redirigirlo a la pantalla de inicio de su rol según la matriz de roles. (→ F-01.AC6)
- **R21** (Por estado) Mientras haya una sesión activa, el sistema deberá mostrar en las vistas protegidas un encabezado con su `fullName`, el nombre de su rol en español y el botón "Cerrar sesión", y en la navegación solo los enlaces a las rutas que la matriz de roles permite a su `role`. (→ F-01.AC6)
- **R22** (Por evento) Cuando el usuario pulse "Cerrar sesión", disponible en toda vista protegida, el sistema deberá cerrar la sesión (efectos) y navegar a `/login` reemplazando la entrada del historial, de modo que volver a una ruta protegida (incluido el botón Atrás) redirija a `/login`. (→ F-01.AC6)
- **R23** (Ubicuo) El sistema deberá mostrar en cada ruta de inicio por rol de la matriz de roles un marcador con un encabezado `h1` con el nombre de la vista y el texto de que la funcionalidad llega en la feature indicada en la matriz, sin datos de pacientes ni acciones. (→ F-01.AC6)

### Privacidad
- **R24** (Ubicuo) El sistema deberá excluir el token, la contraseña, el correo y los datos de `GET /api/v1/me` de toda salida de `console` y de la URL (ruta, query string y hash). (→ F-01.AC6)

## Preguntas abiertas
- [x] **PA-1** Texto exacto de los mensajes: credenciales inválidas (R6), demasiados intentos (R7), conexión (R8), error genérico (R9), validación por campo (R2), sesión expirada (R14, R15), solo personal (R17), error de perfil (R16) y vista "Sin permiso" (R19). **Propuesta:** R6 "Correo o contraseña incorrectos."; R7 "Demasiados intentos. Espera {n} segundos e inténtalo de nuevo." (sin `Retry-After`: "Espera un momento…"); R8 "No se pudo conectar con el servidor. Revisa tu conexión e inténtalo de nuevo."; R9 "No se pudo iniciar sesión. Inténtalo de nuevo."; R2 "Escribe tu correo." / "Escribe un correo válido." / "Escribe tu contraseña."; R14/R15 "Tu sesión expiró. Vuelve a iniciar sesión."; R17 "Esta web es solo para el personal. Los pacientes usan la app móvil."; R16 "No se pudo cargar tu perfil."; R19 "No tienes permiso para ver esta página." → propuesta aceptada (humano, 2026-10-26).
- [x] **PA-2** ¿Hay opción "Recordarme" (sesión que sobrevive al cierre de la pestaña o del navegador)? **Propuesta:** no en el MVP; la sesión vive en la pestaña (D1) y cerrar la pestaña cierra la sesión, lo que conviene en equipos compartidos entre turnos. → propuesta aceptada (humano, 2026-10-26).
- [x] **PA-3** ¿Qué pasa si el token expira (o llega un 401) con un formulario a medio llenar? **Propuesta:** en F-01 se aplica R14/R15 tal cual (se pierde lo no enviado; no hay formularios clínicos aún) y no hay aviso previo; la decisión de avisar N minutos antes o conservar un borrador se toma en F-03-web, que es el primer formulario clínico. → propuesta aceptada (humano, 2026-10-26).
- [x] **PA-4** Pantalla de inicio por rol, rutas permitidas por rol mientras sean marcadores y contenido del encabezado de las vistas protegidas. **Propuesta:** la matriz de `design.md` D7 (RECEPTION → `/recepcion`; NURSE → `/triage`; PHYSICIAN → `/cola`; ADMIN → `/reportes`; `/cola` también para NURSE y ADMIN según F-06), y un encabezado con `fullName`, el nombre del rol en español y "Cerrar sesión". → propuesta aceptada (humano, 2026-10-26).
- [x] **PA-5** Tras un 429, ¿se deshabilita "Ingresar" hasta que pase `Retry-After`? **Propuesta:** sí, deshabilitado durante los segundos de `Retry-After` (60 s si falta la cabecera, que es la ventana de R39 de F-01-api) y se habilita solo al terminar. → propuesta aceptada (humano, 2026-10-26).
- [x] **PA-6** Varias pestañas: con D1 cada pestaña nueva pide iniciar sesión y cerrar sesión en una pestaña no cierra las otras. ¿Es aceptable? **Propuesta:** sí en el MVP (es el mismo comportamiento que tiene el token sin estado de la API, D6 de F-01-api). → propuesta aceptada (humano, 2026-10-26).
- [x] **PA-7** Tras iniciar sesión por una redirección (R18), ¿se vuelve a la ruta que se pidió o siempre a la pantalla de inicio del rol? **Propuesta:** volver a la ruta pedida si la matriz la permite a su rol, y si no, a la pantalla de inicio; la ruta se recuerda en memoria (estado de navegación), nunca en la query string. → propuesta aceptada (humano, 2026-10-26).
