# F-07-web — Diseño

> Este diseño aplica PA-1..PA-9 con la opción (a), que el humano eligió en cada una el 2026-11-13.

## Resumen

`/reportes` deja de ser el dashboard de UI-02-web, que tenía tres `GET /encounters` de conteo, el panel «Atenciones por sede» y la franja «pendiente». Pasa a ser el **tablero de reportes** de F-07, alimentado por un único `GET /api/v1/reports/summary`, y gana la descarga del CSV interno con `GET /api/v1/reports/encounters.csv`.

La web **no calcula ningún indicador**: muestra los números del resumen con el formato del idioma, «Sin datos» en los `null` y el periodo y la hora de cálculo que devuelve la API. Lo único que calcula es la fecha civil de hoy en Bogotá, para proponer el periodo por defecto (D4).

## Impacto en contrato

- Consume **0.9.0**, como ya hace desde DT-02-web: no hay cambio de versión, ni de `CONSUMED_CONTRACT` ni de `EXPECTED_CONTRACT`. `feature_list.json` ya declara `consumes_contract: "0.9.0"`.
- Operaciones nuevas en el código de la web (las publicó F-07-api en 0.8.0):
  - `GET /api/v1/reports/summary?from=YYYY-MM-DD&to=YYYY-MM-DD[&siteId=uuid]` (`ADMIN`) → **200** `ReportSummaryDto`:
    - `period { from, to, siteId|null }`, `generatedAt` y `population { encounters, triaged }`;
    - `timeToTriage { byLevel: LevelTimeStatsDto[], total: TimeStatsDto }` y `timeToCare { byLevel: CareTimeStatsDto[] }`;
    - `compliance { level: 2, maxMinutes, evaluable, compliant, percent|null, notEvaluated }`;
    - `concordance { pairs, exactAgreementPercent|null, weightedKappa|null, underTriagePercent|null, overTriagePercent|null, matrix: int[5][5] }`;
    - `fallback { decisions, suggestions, providers, guards }`, con `CountPercentDto { count, percent|null }`.

    Errores: **400** (formato, `siteId` no UUID o parámetro desconocido; `errors[]`), **401**, **403** y **422** (`from > to` o más de 366 días; `errors[]`), todos en `application/problem+json`. Una sede inexistente o de otro tenant da 200 con la población vacía.

  - `GET /api/v1/reports/encounters.csv?from&to[&siteId]` (`ADMIN`) → **200** `text/csv` con `Content-Disposition: attachment; filename="asclepio-atenciones-<from>_<to>.csv"`. Errores **400**, **401**, **403** y **422**, en `application/problem+json`. Cada descarga la audita la API (`REPORT_EXPORTED`).
- Tipos: `npm run api:types` **sin diff**. Alias nuevos en `client.ts`, solo derivados de `Schemas` y `paths` (R31). Ningún tipo escrito a mano.
- La web no cambia el contrato. **Observación para la API** (fuera de este repo, D8): su CORS expone solo `Retry-After`, así que la web no puede leer `Content-Disposition` desde otro origen. Se propone al humano un cambio menor en `asclepio-api` que no bloquea este slice.

## Impacto en datos

Sin impacto en datos: la web no tiene base de datos ni migraciones.

- El resumen vive solo en la caché de TanStack Query (R30). El periodo y la sede viven en el estado de React.
- El CSV pasa por un `Blob` en memoria y una URL temporal que se revoca después del clic. No entra en la caché ni en el almacenamiento (R27).
- Nada se escribe en `localStorage`, `sessionStorage` ni la URL.
