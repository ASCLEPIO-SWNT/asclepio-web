# UI-02-web — Tareas

Sin migraciones ni cambios de contrato (0.4.0 → 0.4.0). Referencia visual: la maqueta v2 aprobada por el usuario el 2026-10-28 (`../../local-analysis/ui02-maqueta/maqueta-dashboards.html` y `capturas/`; `design.md`, «Referencia visual aprobada»). Orden de ejecución estricto. En cada tarea el `implementer` escribe **primero la prueba** `R<n>:` (bajo `describe('UI-02-web …')`), luego el código, ejecuta la suite completa y solo entonces marca `[x]`. Las pruebas existentes se ajustan únicamente en lo que lista `design.md` («Pruebas existentes que cambian»). No quedan preguntas abiertas: PA-1 a PA-5 están resueltas (usuario, 2026-10-28; PA-3 fijó el refresco automático cada 30 s, que revisa F-03-web D3 y R3) y las tres propuestas de la maqueta v2 quedaron aprobadas (S6). Nada de código de aplicación se toca antes de que el usuario apruebe la spec.

Las tareas se agrupan en **tres etapas**, pensadas para tres `implementer` distintos. Cada etapa termina con la suite completa, el lint, el typecheck y `npm run i18n:check` en verde y con una nota de etapa en `progress/impl_UI-02-web.md` (qué se hizo, pruebas existentes tocadas y desviaciones de la maqueta, si las hubo); la etapa siguiente empieza leyendo esa nota.

- **Etapa A, base compartida (T1 a T5)**: capturas «antes», datos y formateadores compartidos, catálogos i18n, hoja de estilos y componentes de `shared/ui`.
- **Etapa B, los cuatro dashboards (T6 a T9)**: una tarea por pantalla, con la actualización de las pruebas existentes de esa pantalla.
- **Etapa C, marco, rutas y cierre (T10 a T14)**: marca única en el marco privado, rutas, guía de voz y retirada de `PlaceholderPage`, transversales, verificación visual con evidencia y cierre.
